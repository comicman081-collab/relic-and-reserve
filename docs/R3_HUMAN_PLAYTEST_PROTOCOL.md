# RELIC & RESERVE R3 — MVP Human Playtest Protocol

Status date: 2026-08-24 (Asia/Seoul)

Automated PASS is only permission to begin this playtest. It is not a declaration that the game is complete and it does not lift the Windows application/archive hold.

## Candidate session

- Recruit at least five first-time players who have not read the design documents.
- Use a source/editor or other non-held test run only; do not export or package Windows artifacts.
- Start each player on a fresh Stage 1 profile in their preferred Korean or English locale.
- Give only the control legend. Do not explain the investigation, repair, listing or auction solution.
- Record screen, elapsed time, clicks/keyboard actions and spoken think-aloud notes where consent permits.
- After the first auction, replay the same stage once if time permits.

## Five required observations

### 1. Unaided Stage 1 completion

Measure whether the player reaches a recorded SOLD or NO SALE result through the real six-step route: investigate → cite → report → repair → list → auction.

Record every point where the player waits more than 20 seconds, opens Help, backtracks, selects a disabled/irrelevant control or asks the facilitator what to do.

Candidate gate: at least four of five players complete the route without facilitator instruction, and no single step blocks two or more players.

### 2. Listing choice deliberation

Record the selected Fast/Balanced/High price plan and Uncertain/Likely/Certain claim, whether the player rechecks public evidence/condition/provenance, and the stated reason for the choice.

After a low result, observe whether the player changes a relevant listing choice instead of repeating the default blindly.

Candidate gate: at least three of five players can explain one real trade-off before confirming; no one describes Certain as an automatic upgrade or hidden-truth reveal.

### 3. Auction cause comprehension

Immediately after SOLD or NO SALE, hide nothing and ask: “Why did the bidders react this way?” Compare the answer with the first public reason chip and the chosen reserve/disclosure.

Candidate gate: at least four of five players name the primary public cause without developer explanation. Any answer based on a truth field that was never shown is a leakage/comprehension failure.

### 4. Actionable replay change

Show the Stage Clear Evidence/Preservation/Sale axes and one weakest-axis line. On the next run, record whether the player changes the cited evidence, tool/intervention, price plan or disclosure that corresponds to the weak axis.

Candidate gate: at least three of five players make a relevant change, and no player believes a score below the recommendation cancelled the clear or next-stage unlock.

### 5. Visual reading load

For dossier, repair, listing and auction, record long reading pauses, repeated scanning, clipped labels and moments where portraits obscure critical facts. Ask which information was understood from an icon/portrait and which required reading a paragraph.

Candidate gate: zero clipped required controls or critical overlaps; speech stays within two lines; no screen produces the same text-confusion report from two or more players. Repeated pauses identify the next illustration/text-reduction task even if the automated density gate passes.

## Session log

For each player, record:

| Field | Value |
|---|---|
| Locale | KO / EN |
| Stage 1 completed unaided | yes / no |
| Block point(s) | screen + control + elapsed time |
| Listing choice and stated reason | price + claim + reason |
| Correct auction cause | yes / no + answer |
| Weakest axis | Evidence / Preservation / Sale / N/A |
| Relevant replay change | yes / no + action |
| Text/visual friction | screen + observation |
| Technical issue | reproduction steps |

## Decision rule

Passing every candidate gate makes the source a stronger MVP candidate only. Findings are converted into prioritized P0/P1/P2 source tasks, retested headlessly, visually reviewed again and then replayed with people. The game remains incomplete until the user explicitly changes that status and separately authorizes any held Windows application or archive work.
